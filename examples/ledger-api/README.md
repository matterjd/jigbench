# Ledger API (.NET 10)

A tiny .NET 10 minimal API backing the [`../ledger-angular`](../ledger-angular) demo for a
fictitious small business, **Ledger**, that tracks invoices and customers. It exists as a **Jig
fixture** — the target the `.NET` survey adapter's tests run against.

**All data is fake.** The store seeds 4 customers and 8 invoices in memory at startup (no
database, no persistence) — see `Data/LedgerStore.cs`. Nothing here is a real business.

## What's here

- `Program.cs` — minimal-API wiring: OpenAPI (`AddOpenApi` / `MapOpenApi`), CORS for
  `http://localhost:4200`, Kestrel fixed to `http://localhost:5210` (`Properties/launchSettings.json`
  and `builder.WebHost.UseUrls(...)`).
- `Models/` — `InvoiceDto`, `InvoiceLineDto`, `CustomerDto`, `CreateInvoiceRequest`,
  `UpdateInvoiceRequest` (records, with data annotations on the request types).
- `Endpoints/` — minimal-API route maps: `GET /api/invoices`, `GET /api/invoices/{id}`,
  `POST /api/invoices`, `PUT /api/invoices/{id}`, `GET /api/customers`, `GET /api/customers/{id}`.
- `Controllers/ReportsController.cs` — one `[ApiController]`-style controller,
  `GET /api/reports/aging`, kept deliberately alongside the minimal-API maps above so a survey
  tool's fallback path has both shapes to find.
- `Data/LedgerStore.cs` — the in-memory seeded store (thread-safe, deterministic).
- `openapi.v1.json` — a **recorded snapshot** of `GET /openapi/v1.json`, verbatim. The dotnet
  survey adapter's tests read this file instead of running `dotnet run`. Refresh it whenever a
  model or endpoint shape changes (see below).

## Run it

```bash
dotnet run
```

Serves on `http://localhost:5210` (fixed — see `Properties/launchSettings.json`). Try:

```bash
curl http://localhost:5210/api/invoices
curl http://localhost:5210/openapi/v1.json
```

## Test

```bash
dotnet test ../ledger-api.tests
```

`LedgerApi.Tests` (xUnit + `WebApplicationFactory`) covers: invoices list returns all 8 seeded
rows, get-by-id 404s on an unknown id, POST creates an invoice (and it then appears in the list),
POST with no line items 400s, PUT updates an existing invoice and 404s on an unknown one, the
customers list/get endpoints, the OpenAPI document is served and contains `/api/invoices`, and
the `ReportsController`'s aging route responds.

## Refreshing `openapi.v1.json`

The snapshot is regenerated by hand, not by a build step, so it only changes when someone means
it to:

```bash
dotnet run &                                   # or start it any way you like
curl http://localhost:5210/openapi/v1.json -o openapi.v1.json
# stop the server (find its PID via the port, never by process name), e.g.:
#   netstat -ano | grep ':5210' | grep LISTENING
#   taskkill /PID <pid> /F
```
