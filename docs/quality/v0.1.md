## 6. What QA could not verify

Per `DELIVERY-TEAM.md` §3's physics rule — an agent's clicks run in an isolated profile, so a
narrow class of checks only count on Matter's own machine:

- **The work laptop.** Every gate above ran on this desktop only. Decision 16 (Ollama install)
  and the laptop's own no-admin constraint (`FEASIBILITY.md`) are unverified until Matter opens
  `npx jigbench` there.
- **Matter's real repos.** All smokes and the live walkthrough ran against the `examples/`
  fixtures (Ledger Angular + .NET). No pass here proves behavior against a real, larger,
  differently-shaped Angular/.NET repo.
- **The Claude Desktop installer against a real config.** `jigbench mcp install
  --claude-desktop` prints a diff and only writes with `--yes`; QA did not run `--yes` against a
  real `claude_desktop_config.json` (would mutate a live agent config outside the repo — out of
  QA's write scope and irreversible-in-place without a backup Matter would need to keep himself).
- **`claude mcp list` health end-to-end.** `mcp-smoke.sh`'s global-state step (real `npm link` +
  `claude mcp add` + `claude mcp list`) is opt-in (`JIGBENCH_SMOKE_GLOBAL=1`) and was **not** run
  this pass, by the task's own instruction — it mutates the current machine's global npm and
  `~/.claude.json`. The read-only MCP e2e (real SDK Client over stdio) substitutes for it and
  passed; the wave-4 council's own live verification (§3) is the only real `claude mcp list ✔
  Connected` evidence on record, from 2026-09-06 before this QA pass.
- **The RELEASE hold gesture's visual (filling ring, ember).** QA drove the full mark → drafted →
  released → in-the-shop → trial-fit ladder over the REST API (`trialfit-smoke.sh`) and confirmed
  in the live UI that a quick click on RELEASE correctly **cancels** ("released before the weight
  — nothing written" — the safety half of the design). The Browser pane's automation has no raw
  mousedown/mouseup primitive to sustain an ~800 ms hold, so the fill-and-commit half of that
  specific gesture, and its ring/ember animation, is unverified by QA — `docs/team/v0.1/demo-1.md`
  names it as a check for Matter's own hand.
